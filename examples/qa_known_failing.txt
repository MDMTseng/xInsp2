# Format:  <qa_dir_name>: <reason>
# Lines starting with '#' and blank lines are ignored.

# WHAT THIS IS
# A quarantine is NOT a mute. A test listed here still RUNS every time; the gate
# just does not go red because it failed - instead it prints a loud KNOWN-FAIL
# line with the reason below. Two things keep the list honest:
#   * if a quarantined test starts PASSING, run_qa reports it as an UNEXPECTED
#     PASS and FAILS - you must delete its line here (the list cannot rot green);
#   * `python tools/run_qa.py --strict` ignores this file entirely and treats
#     every failure as fatal (the raw truth / the eventual clean-suite gate).
#
# WHY THESE ARE HERE (see docs/ci-gate-known-failures.md for the full write-up)
# When the day-1 gate (tools/gate.py) was first stood up, 13 of 25 qa examples
# were already red on master - the gate did its job and surfaced a pre-existing
# broken suite. 12 of the 13 are the "dead-API scripts": their inspect.cpp still
# uses the RETIRED VAR(...) / EMIT(...) macros and the legacy `xi_inspect_entry(
# int frame)` entry, all removed from the SDK headers, so they no longer compile
# (C3861 'EMIT'/'VAR' not found, C2065 'frame' undeclared). Rewriting/deleting
# those scripts is adoption-map item 4 ("fix or delete the 32 dead-API scripts"),
# a separate branch - NOT the CI-gate branch. They are quarantined so the gate is
# usable now (it catches NEW breakage) and self-empties as item 4 lands.
#
# Retire a line the moment its script is fixed on the examples branch.
