## Studied → new corner cases / findings for next rounds
1. **FINDING (real gap): `SafeStateEvent.ts_ms` is never logged.** The event
   carries a wall-clock timestamp but `LoggingSafeStateSink::emit` doesn't print
   it. A safety transition log with no timestamp is weak forensics. → schedule a
   code fix + a unit asserting the line carries the ts. (Round 8 polish.)
2. **Double output by design?** `emit` writes to stderr *and* the log `FILE*`
   when both exist; `fe_main` passes `nullptr` to dodge it. Decide if the
   contract should be "log XOR stderr". Low priority; note in the design doc.
3. **Factory is type-insensitive today** (always logging). When real PLC
   transports land, `"Modbus"` vs `"modbus"` and unknown-type handling need
   defined behavior (error? fallback + warn?). → add cases when a 2nd sink exists.
4. **Concurrency**: `enter_safe_state` is only called from the FE monitor thread
   today, but the contract doesn't say single-threaded. Two threads `fprintf`-ing
   the same `FILE*` can interleave. → document "call from one thread" or add a lock.
5. **Crash-report parser still untested** (`enrich_from_crash_report` is
   file-static in `fe_main.cpp`). → Round 5: extract to a header + CR-U*.
